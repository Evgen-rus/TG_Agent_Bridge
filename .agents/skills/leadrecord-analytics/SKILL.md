# Повторная аналитика LeadRecord

Работай через SSH → lkctl → localhost Agent API. Не читай БД или файлы pipeline напрямую. Начни с lkctl capabilities. На настроенном VPS read-команды вызывает lkctl, compute — lkctl-compute. Токены уже загружаются wrappers; не выводи их.

Бизнес-проект — клиент + точный тег [LRчисло] + название. Канал перед тегом и источник после названия — части одного бизнес-проекта. Редкие группы объединяют несколько LR. Не объединяй по похожему имени. Точные названия могут содержать открытые бизнес-номера.

## Порядок

1. Уточни даты, если их нет. Даты включительны. Найди клиента через clients find, затем analytics groups и projects list. Прочитай все страницы (total/limit/offset).
2. Выбери существующую группу; вызови analytics plan --group ID --period START:END. Покажи клиент, LR, имя, состав, сохранённую таблицу/вкладку, период. Используй уже данное подтверждение, не спрашивай повторно без изменения состава/источника.
3. Если initial setup отсутствует, сообщи, что нужна первоначальная настройка в ЛК. Не угадывай таблицу, вкладку, колонки или категории.
4. Если найдены новые проекты с теми же LR, покажи их ID/названия и спроси, какие добавить. Передавай только явно подтверждённые добавления в --confirm-projects ID,ID. Не удаляй исторические проекты.
5. После разрешения на обновление/расчёт: analytics prepare --group ID --period START:END. Сохрани run_id. Опрашивай analytics result --group ID --run RUN_ID до окончания match job; при queued/running жди, не создавай новый run. На failed остановись.
6. После matched вызови analytics run --group ID --run RUN_ID. UNKNOWN_STATUSES означает вопрос человеку. Покажи значения и разрешённые категории; передай только явный ответ через analytics confirm-statuses --group ID --run RUN_ID --assign 'Статус=Категория', затем повтори run. Не назначай категории по смысловой догадке.
7. Опрашивай result до completed. На ошибке сообщи код/request_id и выполненные этапы; не повторяй новый расчёт автоматически.
8. Получи export_id из результата и скачай: lkctl-compute analytics download --group ID --id EXPORT_ID --output /absolute/new/report.xlsx. Команда возвращает путь/размер/sha256. Для файла на другой машине требуется перенос; удалённый путь не является локальным вложением.
Для ограниченного ключа Рика вместо download используется SSH-команда fetch GROUP_ID EXPORT_ID: stdout содержит XLSX; Bridge сохраняет файл локально и отправляет его владельцу. Произвольный удалённый --output этим ключом недоступен.

9. Верни итоги с точным периодом/источником и готовый Excel. Отправку в Telegram выполняет существующий механизм Bridge только в рамках запроса пользователя; не создавай нового sender и не заявляй доставку без подтверждения.

## Чтение результата

Read JSON не содержит сырые лиды. Excel может содержать строки лидов: передавай только запрошенный отчёт, не печатай его строки в чат/логи.

Идентификации ЛК считаются по imported_at; статусный отчёт — по выбранной клиентской колонке даты. Их объёмы могут различаться. Недозвон не равен «не обработано». Качественные входят в сигнал спроса, не складывай их. Не подменяй выбранный период месячным/общим отчётом. Текущий статус проекта не является историческим.

Для Рио-Люкса менеджеры и AI — отдельные анализы; лид может присутствовать в обоих. Сначала проверь реально настроенные вкладки/группы и подтверди выбор. Итоги не складывай и не дедуплицируй между потоками. Если две вкладки отдельно не настроены, не переключай сохранённый mapping самовольно.

Exit codes: 0 успех, 1 ошибка, 2 неверный ввод/needs_input. needs_input — остановка с конкретным вопросом, не выполненный анализ.
