# Повторная аналитика LeadRecord

Работай через SSH → lkctl → localhost Agent API. Не читай БД или файлы pipeline напрямую. Начни с lkctl capabilities. На настроенном VPS read-команды вызывает lkctl, compute — lkctl-compute. Токены уже загружаются wrappers; не выводи их.

Бизнес-проект — клиент + точный тег [LRчисло] + название. Канал перед тегом и источник после названия — части одного бизнес-проекта. Редкие группы объединяют несколько LR. Не объединяй по похожему имени. Точные названия могут содержать открытые бизнес-номера.

## Порядок

1. Уточни даты, если их нет. Даты включительны. Найди клиента через clients find, затем analytics groups и projects list. Прочитай все страницы (total/limit/offset).
2. Сохраняй общий диапазон start/end и отдельный упорядоченный список periods. Для обычного запроса это один период. Не добавляй месячную или недельную разбивку, если владелец её не просил. Если владелец просит разбивку выбранного диапазона, включи сначала полный диапазон одним периодом, затем его части в хронологическом порядке. Для недель используй календарные недели с понедельника по воскресенье, для месяцев — календарные месяцы. Крайние части обрежь по границам диапазона и сохрани, даже если в них один или два дня. Общий период пропускай только по явной просьбе владельца получить одну разбивку без общего периода. Все периоды передавай в одном Excel; показатели общего диапазона и его частей не складывай. Не переупорядочивай периоды. Допускаются пересечения, максимум 64 периода и 366 календарных дней в общем диапазоне. При неоднозначной разбивке спроси точные даты.
3. Вызови analytics plan --group ID --period START:END по общему диапазону. Покажи клиента, LR, имя, состав проектов, сохранённую таблицу/вкладку, общий диапазон и каждый период в порядке отчёта. Используй уже данное подтверждение, не спрашивай повторно без изменения состава/источника/периодов.
4. Если initial setup отсутствует, сообщи, что нужна первоначальная настройка в ЛК. Не угадывай таблицу, вкладку, колонки или категории.
5. Если найдены новые проекты с теми же LR, покажи их ID/названия и спроси, какие добавить. Передавай только явно подтверждённые добавления в --confirm-projects ID,ID. Не удаляй исторические проекты.
6. После подтверждения передай каждую запись как отдельный повторный --period START:END в analytics prepare --group ID. Сохрани run_id. Опрашивай analytics result --group ID --run RUN_ID до окончания match job; при queued/running жди, не создавай новый run. На failed остановись.
7. После matched вызови analytics run --group ID --run RUN_ID. UNKNOWN_STATUSES означает вопрос человеку. Покажи значения и разрешённые категории; передай только явный ответ через analytics confirm-statuses --group ID --run RUN_ID --assign 'Статус=Категория', затем повтори run. Не назначай категории по смысловой догадке.
8. Опрашивай result до completed. На ошибке сообщи код/request_id и выполненные этапы; не повторяй новый расчёт автоматически.
9. Получи export_id из результата и скачай: lkctl-compute analytics download --group ID --id EXPORT_ID --output /absolute/new/report.xlsx. Команда возвращает путь/размер/sha256. Для файла на другой машине требуется перенос; удалённый путь не является локальным вложением.
Для ограниченного ключа Рика вместо download используется SSH-команда fetch GROUP_ID EXPORT_ID: stdout содержит XLSX; Bridge сохраняет файл в отдельную папку задачи и использует только проверенный `download_filename` из метаданных LeadRecord. Произвольный удалённый --output этим ключом недоступен.

10. Верни итоги с точным списком периодов/источником и готовый Excel. При запросе разбивки проверь, что расчёт и Excel содержат общий диапазон первым, затем все его части; в ответе покажи итоги общего диапазона и динамику по частям. Не выдавай одну разбивку вместо общего отчёта, если владелец явно этого не просил. Для перекрывающихся периодов показывай показатели по каждому периоду отдельно, не складывай их в общий итог. Отправку в Telegram выполняет существующий механизм Bridge только в рамках запроса пользователя; не создавай нового sender и не заявляй доставку без подтверждения.

## Чтение результата

Read JSON не содержит сырые лиды. Excel может содержать строки лидов: передавай только запрошенный отчёт, не печатай его строки в чат/логи.

Идентификации ЛК считаются по imported_at; статусный отчёт — по выбранной клиентской колонке даты. Их объёмы могут различаться. Недозвон не равен «не обработано». Качественные входят в сигнал спроса, не складывай их. Не подменяй выбранный период месячным/общим отчётом. Текущий статус проекта не является историческим.

Для Рио-Люкса менеджеры и AI — отдельные анализы; лид может присутствовать в обоих. Сначала проверь реально настроенные вкладки/группы и подтверди выбор. Итоги не складывай и не дедуплицируй между потоками. Если две вкладки отдельно не настроены, не переключай сохранённый mapping самовольно.

Exit codes: 0 успех, 1 ошибка, 2 неверный ввод/needs_input. needs_input — остановка с конкретным вопросом, не выполненный анализ.
