# 04. Экран за экраном: спецификация

## Rick

### R-01 / Обзор

**Цель:** за 5 секунд понять, есть ли событие, требующее решения.

- Шапка `Rick`, доступность/статус сервиса только на реальном health endpoint, аватар учётной записи.
- Hero `Под контролем` или `Требует решения` без выдуманных счётчиков.
- Главная карточка: `источник` → `суть` → `предложение` → `Открыть`, дату/время, статус по факту.
- Короткая лента свежих событий. Недоступные участнику чаты не показывать.
- CTA «Спросить Рика».

### R-02 / События (Inbox)

Список эпизодов, не «все сообщения» подряд. Каждый содержит заголовок, краткую выжимку, название чата, timestamp, состояние проверки. Поиск, фильтр чат/состояние — если данные и API поддерживают. Пагинация/cursor, обновление без скачков списка.

### R-03 / Карточка события

Разделы: `Суть`, `Контекст`, `Предложение Рика`, `Решение`. При наличии — цитата и источник. Действия `Принять`, `Уточнить`, `Отклонить` только в рамках проверенных existing workflow. Для опасных и dev-действий отдельный контроль прав.

### R-04 / Диалог с Риком

История owner-чата при наличии разрешённого API, строка ввода, микрофон как future/conditional, режим выбора чата при неоднозначном запросе, явное отображение статуса обработки, ошибки лимита Codex без автоматического повторения дорогостоящих вызовов.

### R-05 / Самоаудит и напоминания

Существующие предложения самопроверки, статусы `Принять / Отклонить / Позже`, только при наличии данных и разрешений. Напоминания показывать как real stored reminders. Для Дмитрия права оцениваются отдельно.

## Sally

### S-01 / Главная

**Цель:** вернуться к сделке и сразу увидеть полезное действие.

- Приветствие/контекст дня — без фиктивных KPI.
- Последняя активная тема, ссылка «Продолжить».
- Рекомендации из реальной истории (не считать все события «риском»).
- Блок договорённостей при наличии записей.
- Быстрый переход к сделкам.

### S-02 / Сделки

Каждый элемент = доступная тема закрытой Telegram forum-супергруппы. Название, последнее событие, дата, indicator наличия рекомендации/подтверждения. Фильтр/поиск в пределах разрешённых сделок. Пустая тема не должна выглядеть как закрытая сделка.

### S-03 / Карточка сделки

Заголовок темы, хронология событий/сообщений и ответы Салли, срез фактов и рекомендаций (если API извлекает), реальные обещания. Основной CTA `Обсудить с Салли`. Важно не слить сообщения другой сделки из-за неверного topic id.

### S-04 / Диалог внутри сделки

Сообщения менеджера, ответы Салли, цитаты/вложения, поле ввода. В интерфейсе явно указан контекст темы. Copy draft, ручная отправка клиенту, отметка неизвестного факта. Мобильный вид при длинной транскрипции, 2+ изображениях и ошибке STT.

### S-05 / Договорённости

Список из текущего реестра только видимых тем. Обязательство, источник, тип, срок, статус, последние изменения. Обязательно различать «напоминание должно прийти» и «подтверждено, что пришло».

### S-06 / Проверка фактов

Старое утверждение → новая формулировка → цитата-основание. Явные `Подтвердить` / `Отклонить`. Пока нет решения, нельзя показывать новую информацию как сохранённую память. Кнопки привязаны к корректному id/ревизии episode. Повтор нажатия безопасен.

## Общие экраны

### G-01 / Вход

Только invite-only три пользователя. Единый identity provider по возможности, отдельные разрешения для продуктов. Session cookie `Secure`, `HttpOnly`, `SameSite` и серверная проверка прав. Не показывать публичную регистрацию.

### G-02 / Настройки

Имя, выбранное приложение, выход из аккаунта, помощь/сборка. Не показывать токены, ключи, Codex ID, системные env. Не разрешать менять модель или серверные права без отдельного ограниченного интерфейса.

### G-03 / Ошибки

Нет сети, истёкшая сессия, ошибка backend, лимит Codex, недоступная тема, неподтверждённая операция, конфликт ревизий, запрет доступа. В каждом случае — понятное безопасное действие.

## Демонстрационные данные в HTML

Данные специально придуманы для презентации. Они не извлечены из реальных сообщений и не должны автоматически попадать в тестовые или production БД. Указанные «Птицефабрика», «Коммерческое предложение» и события показаны только как примеры формата.
