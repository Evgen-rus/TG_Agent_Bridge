# Rick + Sally — комплект дизайн-концепции v1.0

**Дата:** 16 октября 2026. **Статус:** дизайн-проект и интерактивный демонстрационный прототип. **Не production-приложение.**

## Начать здесь

1. Откройте **`prototype/index.html`** в браузере ПК: всё работает локально, без сборки, сети и подключения к агентам.
2. Переключайте **Rick A / Rick B / Sally A / Sally B**. Внутри экрана нажимайте вкладки, карточки, кнопки, проверяйте состояния и диалог.
3. Посмотрите **`preview/overview.png`** — один общий лист с четырьмя главными экранами. По отдельности есть `rick-a.png`, `rick-b.png`, `sally-a.png`, `sally-b.png`, а также `*-detail.png` с карточками.
4. Прочитайте **`01_PRODUCT_CONCEPT.md`** и **`02_UX_FLOWS.md`**.
5. Отправьте **`PROMPT_CODEX_DESIGN.md`** вместе с ZIP в Codex: он должен сначала создать и показать уже рабочий *свой* прототип, затем согласовать дизайн.
6. После согласования — **`PROMPT_CODEX_BUILD_DEPLOY.md`** для реализации и автоматического деплоя с проверками.

## Важные границы

- **Rick:** Евгений + Дмитрий. Отдельный рабочий помощник. Не отправляет сообщения в клиентские чаты автоматически.
- **Sally:** Евгений + Сергей. Sales Buddy, работа со сделками через темы отдельной Telegram-супергруппы.
- Общий frontend-компонентный слой, но **отдельные PWA, авторизация, права и данные**.
- В прототипе **демоданные, никаких API-запросов**, поэтому нажатия ничего не меняют в Telegram, SQLite, Git или VPS.
- По текущему репозиторию уже существуют два разных сервиса, Rick (`rick.service`) и Sally (`sales-buddy.service`). Фактические конфигурации должны быть проверены Codex перед деплоем.
- Поддержка браузером установки отдельных PWA будет зависеть от происхождения HTTPS, настроек манифестов и браузера. Для окончательных сборок нужны два scope/start_url и независимая идентичность приложений.
