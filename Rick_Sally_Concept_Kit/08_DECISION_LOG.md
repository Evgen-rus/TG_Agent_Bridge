# 08. Зафиксированные решения и вопросы

## Уже определено

- Два продукта: Rick (Евгений + Дмитрий), Sally (Евгений + Сергей).
- Два installable PWA, общие reusable frontend-компоненты, жёсткая изоляция данных/доступов.
- Основной AI, память и бизнес-логика остаются в текущем TG_Agent_Bridge.
- Сначала 4 дизайн-концепции и утверждение, затем функциональная разработка и деплой.
- После утверждения Codex выполняет полный цикл самостоятельно: код → тесты → commit → push → pull на VPS → настройка → перезапуск → проверки.
- Никаких секретов в чат и Git.

## Нужен выбор пользователя по прототипам

1. Rick A или B, либо сочетание (указать компоненты).
2. Sally A или B, либо сочетание.
3. Какой главный экран должен быть по умолчанию: входящие события или прямой AI-диалог? Для Sally: список сделок или рекомендации?
4. Хочется ли показывать чат отдельной вкладкой или в карточке контекста? Рекомендуем: Rick — отдельная вкладка, Sally — чат внутри сделки.

## Действительно может потребовать уточнения перед production

- Имена/адреса доменов, способ SSH (Codex должен проверить окружение, не просить лишних данных).
- Конкретные права Дмитрия в Rick по отслеживаемым чатам; никакого автоматического owner-доступа.
- Какие Telegram-темы Сергей вправе видеть через PWA, и есть ли ограничения помимо участия в группе.
- Подтверждение способа входа для трёх пользователей (invite + пароль/passkey/доверенная авторизация).
- Фактическая доступность совместимых Codex-вызовов из web API и корректной сквозной синхронизации с Telegram.
