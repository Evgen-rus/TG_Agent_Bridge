# 02. Сценарии и информационная архитектура

## Глобальная навигация

### Rick

`Обзор` | `События` | `Диалог` | `Ещё`

- **Обзор**: один главный смысловой блок: «Требует моего решения», ниже события и обзор статуса.
- **События**: эпизоды отслеживаемых рабочих чатов, фильтры только по реальным признакам (чат, дата, состояние).
- **Диалог**: owner-разговор с Риком; отдельный вопрос может потребовать выбора адресата/чата.
- **Ещё**: подтверждённо доступные напоминания/самоаудит/настройки, без доступа к чужим секретам и внутренним логам.

### Sally

`Главная` | `Сделки` | `Договорённости` | `Ещё`

- **Главная**: вернуться к текущим темам и рекомендациям; ссылка «Спросить Салли» требует выбрать контекст сделки.
- **Сделки**: тема Telegram = сделка. Поиск по доступным темам и переключение.
- **Договорённости**: только имеющиеся записи, статус, срок, источник; не выдумывать просрочку при задержках доставки.
- **Ещё**: настройки и справка. Отдельная глобальная «AI-поиск по всем клиентам» — не включать без явных прав и архитектуры.

## Rick: E2E-истории

### R1. Предложение ответить

1. Пользователь видит карточку «нужно решение» с источником/временем.
2. Тапает → открывается полная карточка: факты переписки, вариант ответа, неизвестное.
3. Согласен → подтверждает действие доступного штатного механизма; на уровне PWA нельзя обходить проверку owner.
4. Не согласен → правит текст или просит уточнить; итог сохраняется в правильном эпизоде.
5. Результат: явная отметка состояния, не скрывать неопределённость доставки.

### R2. Спросить Рика про обсуждение

Обзор → диалог → вопрос «Что по обсуждению X?» → если адресат неоднозначен, показ выбора чата → обоснованный ответ с контекстом. Новая сессия PWA не должна создавать чужой Codex thread.

### R3. Режим разработчика и опасные действия

Только роль с нужными серверными правами. Явные подтверждения, аудит. Возможность Дмитрия пользоваться обычным Rick не означает доступ к `/dev`, рестарту или изменению памяти.

## Sally: E2E-истории

### S1. Быстрый ответ клиенту

Главная → `Сделки` → тема «Птицефабрика» → `Спросить Салли` → «Как ответить на вопрос о сроках?» → совет/черновик → скопировать → менеджер сам отправляет клиенту. Черновик и факт не смешивать.

### S2. Проверка договорённости

Главная/Сделка → «Договорённости» → запись «Обещали отправить КП» с цитатой и датой → статус и варианты уточнения. Изменения проходят через существующий контракт, не через прямое редактирование SQLite на клиенте.

### S3. Подтверждение спорного факта

Салли предлагает заменить подтверждённый факт → показывает старую запись, новую версию и основание → `Подтвердить` или `Отклонить` → до решения изменение памяти не применяется. Права текущего участника, актуальность и ревизия проверяются сервером.

### S4. Голосовое/вложение

Менеджер выбирает сделку → прикладывает материал → видит стадии «получено», «обрабатывается», «готово/не удалось» → ответ Салли. Сама возможность отправлять файл через PWA реализуется только при безопасном внедрении существующего пайплайна.

## Микровзаимодействия

- Тап по карточке: открытие детали с сохранением выбранного раздела при возврате.
- Подтверждения: модалка или явные кнопки в карточке, без мгновенного применения при случайном свайпе.
- Копирование черновика: короткое ненавязчивое уведомление.
- «Обрабатывается»: честный статус без обещания точного времени окончания.
- Offline: разрешён только просмотр ранее загруженного несекретного UI-каркаса, не кэшировать клиентские сообщения без отдельной оценки рисков.
- Empty state: «Здесь пока нет событий»; не добавлять фиктивные рекомендации.
- Error state: конкретно «Не удалось отправить. Повторить?». Идемпотентные запросы должны исключать дубли.

## Навигация при 360 px

- Высота bottom-nav ~64 px + `env(safe-area-inset-bottom)`.
- Цель касания 44–48 px; основные действия снизу в зоне большого пальца.
- В поле ввода есть доступ к выбору контекста сделки/чата; панель ввода поднимается над системной клавиатурой.
- Текст длиннее 2 строк в карточках аккуратно обрезается; детали раскрываются без потери информации.
- Чат: ограничить ширину пузырей, показывать временные метки и различать ответ AI/человека/системы.
