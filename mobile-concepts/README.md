# Rick + Sally — четыре React-концепции

Дизайн-фаза, 16 октября 2026. Весь контент вымышлен. Никаких запросов к Telegram,
Codex, SQLite или ботам; нет постоянного хранения переписки. Выбор дизайна не сделан.

## Запуск в PowerShell

```powershell
cd D:\My_dev_project\TG_Agent_Bridge\mobile-concepts
npm.cmd ci
npm.cmd run dev -- --port 5173 --strictPort
```

Открыть http://127.0.0.1:5173/. Параметр `?concept=signal`, `command`, `ledger`
или `momentum` открывает соответствующий вариант. Переключение концепции сбрасывает
её демосостояние. Размеры 360/390/430 доступны на настольной странице; на телефоне
используется вся ширина. Переключатель состояний доступен и на мобильном экране.

```powershell
npm.cmd run build
npm.cmd run lint
npm.cmd test
```

Сборка — `dist/`; запускать через HTTP, а не двойным щелчком по HTML.
Зависимости нужны при установке, шрифты и интерфейс не используют внешние CDN.
Это локальное preview, не ссылка для доступа с другого телефона.

## Варианты для выбора

| Концепция | Главное действие | Отличие |
| --- | --- | --- |
| Rick A / Signal | Разобрать входящее предложение | Спокойная лента, графит и фиолетовый |
| Rick B / Command | Спросить в контексте чата | Крупный вопрос, быстрые действия, синий и бирюза |
| Sally A / Ledger | Вернуться в тему-сделку | Линейный список, хронология, бумага и зелёный |
| Sally B / Momentum | Подготовить следующий шаг | Крупный блок действия, шалфей и насыщенный зелёный |

Общие AppShell, навигация, карточки, кнопки, диалог подтверждения, состояния,
типографика. Разные композиции главной; Rick и Sally не делят данные и диалоги.
Демосообщения Sally привязаны к выбранной теме, Rick требует явный контекст.
Ответы фиксированные и прямо обозначены как демонстрационные.

## Карта экранов и сценарии

- Rick: Обзор → События (поиск/фильтр) → Карточка → Источник → Принять/Отклонить
  с подтверждением. «Уточнить» → Диалог с выбранным чатом. Диалог доступен отдельно.
- Rick: Ещё → Самоаудит (карточка гипотезы), демонапоминание, справка.
- Sally: Главная → Сделки (поиск/фильтр) → Карточка → Источник, история, память,
  договорённость. Карточка → Диалог → Черновик → Копирование.
- Sally: Карточка → Проверка факта → Было/Предлагается/Основание → Подтвердить
  или отклонить. Повторное решение заблокировано. Договорённости → нужная сделка.
- Общее: loading, empty, error/retry, offline, stale, access-denied, Codex limit,
  source-unavailable. Пустой поиск, needs-context и processing возникают в сценариях.

## Расхождения с комплектом и ограничения

1. Комплект описывает спорные замены фактов Sally как обязательно требующие
   подтверждения. В актуальном `agentbridge/sales/service.py` обычный анализ вызывает
   `validate_result(..., check_semantics=False)`; обычные замены проходят без нового
   review. `storage.decide_fact_review` сохраняет прежний контракт для ожидающих
   review (тема, доставленное сообщение, membership в обработчике, актуальность,
   повторные решения). Карточка здесь — UX-пример для выбора, не заявление о том,
   что любой новый факт сейчас проходит именно так. ARCHITECTURE.md уже описывает
   relaxed path, а некоторые абзацы README и комплекта описывают прежний процесс.
2. Rick остаётся suggest-only и owner-only в Telegram (`telegram/bot.py`).
   «Принято в демо» не означает отправку клиенту и не применяет код/правила памяти.
3. Sally работает в собственной forum-супергруппе, `(chat_id, topic_id)` — сделка,
   отдельные main/provider/storage и `runtime/sales_buddy`. Это не owner-диалог Rick.
4. Веб-аккаунты Евгения/Дмитрия/Сергея, invite/login, ACL, API adapter, два PWA,
   файлы, голос, реальные статусы и безопасная интеграция — фаза 2. Их нет в демо.
5. Реестр договорённостей уже существует (`sales/commitments.py`), но здесь только
   вымышленные записи: без KPI, сумм, воронки и выдуманных сроков доставки.
6. Цвета основаны на токенах комплекта; вторичный текст и тёмные акценты осветлены
   для читаемости. Иконки Lucide, без логотипов сторонних продуктов.

Production-сервисы и данные не изменялись. VPS не обследовался: эта фаза не требует
живого доступа. Приложенный HTML изучен по исходнику и скриншотам; открытие `file:`
в браузере заблокировано политикой протоколов, интерактивная проверка относится
к новому React-приложению. Локальный Sites workflow использован без публикации.

## Что выбрать

Rick A/B (или элементы обоих), Sally A/B (или элементы обоих), главную точку входа
для каждого и удобную плотность текста. Например: «Rick A с быстрым вопросом из B;
Sally A с блоком следующего шага из B». Затем можно запускать фазу 2 отдельно.

Дизайн выбран: Rick A / Signal, Sally A / Ledger. Production UI открывается по
`/rick/` и `/sally/`, исходное демо остаётся по `/` при локальном Vite-запуске.
Backend, авторизация, ограничения и деплой: [web adapter](../agentbridge/web/README.md).
Сгенерированные снимки и промежуточные замеры дизайн-фазы удалены из main после
выбора; исходные материалы комплекта и Git-история сохранены.
